# 验证与复现

## 1. 无数据即可复核

在仓库根目录运行 `python scripts/verify_archive.py`。检查归档原件SHA256、六设置MAE差值及90组记录数量。原训练检查点/预测文件在打包时逐一核验过，但未随仓库分发，所以下载者不能仅凭索引再次验证缺席的原件。

安装依赖后运行 `python -m unittest discover -s tests -v`。检查可移植核心与历史函数的AST完全相同、单元平移不变性、单例排除、梯度及分支相同初始化。

## 2. 使用自己的授权数据

按照 [输入契约](../data/README.md) 准备 NPZ，然后运行：

```bash
python scripts/train.py --data data/fold0_rank8.npz --out runs/fold0_rank8_seed17 --seed 17 --device cuda
```

固定100次 full-batch AdamW 更新，各分支按自身TUNE MAE选检查点。输出 `latest.pt`（模型、优化器、所选模型与epoch）、`predictions.npz`、`result.json`。分支顺序保存于结果JSON。模型没有dropout，初始化后优化循环没有随机采样；新入口不改变历史数值核心。

再次运行相同命令会核验已完成结果并退出；存在中间检查点时继续。互斥锁阻止同一输出目录重复启动。异常退出遗留的锁只能在确认原进程结束后手动处理。运行环境和不同硬件可能导致浮点差异，不能宣称跨设备逐位相同。

完成两个维度、三个队列、三外折、五种子后才能对应历史实验覆盖；一个fold的训练不等于完整复现。新入口只输出单折MAE，历史来源/种子交叉bootstrap方法见原始分析脚本及研究报告，不能用单次MAE冒充统计确认。

## 3. 历史环境与新入口的界限

历史训练使用 PyTorch 2.3.1+cu118 / RTX4060 Laptop GPU。`requirements.txt` 是可安装的兼容范围，不是声称已经验证过所有版本的锁文件。历史原脚本仍保留其依赖关系，用于追溯，不能直接在新机器运行。受限数据、操作系统进程控制、关机机制和绝对本机路径不属于可移植训练接口。

## 4. 阅读结果

MAE越低越好；gain = 对照MAE − 候选MAE。C/N为全群体冲突/非冲突；匹配A的定义基于有共同支持的来源—评分单元，不能用全群体C−N代替。历史置信区间是开发数据上的探索区间，不覆盖全部模型搜索过程，未作多重比较校正。
